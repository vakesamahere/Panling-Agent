## 操作心得
- pathfinder 要 `canDig=false`（冒险地图）
- `goto` 可能挂住不返回，HTTP eval 有 60s 超时；必要时 `bot.pathfinder.stop(); bot.clearControlStates()`
- 进门问题（已解决）：mineflayer 对 1.8 门的碰撞箱算错（打开的门仍按关闭形状碰撞，shapes 只看 metadata 下半）。
  解法：门打开后，客户端本地 `bot.world.setBlockStateId(门两格,0)` 设为空气，再 look + forward 走过去（服务器不校验，合法）。铁门同理（压力板开门后清本地方块）。
- pathfinder 走到压力板/按钮格子经常 PathStopped；直接 `lookAt`+`setControlState('forward')` 小步走更可靠

## 安全层（safety.js，已接入 bot.js 的 h.water / h.roomnav）
- **水上安全**：`h.water.start()/stop()/state()`。每 tick 若 `entity.isInWater` → 按住 jump 上浮（1.8 水里 +0.04/tick 浮力 > 0.02 重力），并朝最近岸 look+forward。防淹死。默认 off，需 start()。
- **传送房导航**：`h.roomnav.triggers(r)` 列出附近压力板/按钮/门/传送门；`h.roomnav.tryAll()` 逐块 look+forward 踩，直到 `forcedMove`/`teleport` 触发。**不要在这些浮空房用 pathfinder**（虚空被当可走格）。walkTo 带 teleport/death 监听。
- 用法：先 `h.water.start()`；在传送房 `await h.roomnav.tryAll()`。
- **goto 超时**：`h.goto(x,y,z,range,timeoutMs=8000)` 已加超时+auto-stop，防 pathfinder 在浮空房挂死（原无超时，eval 等满 60s，bot 卡死）。超时抛 `goto-timeout x,y,z`。
- **水上安全默认开**：bot 启动即 `h.water.start()`。pathfinder 不会游泳，水坑/水洼会让 bot 淹死；此层自动上浮+找岸。
- **村長入口板**：abs(1684,143,113)，从村庄(1689,140,138)去要穿过一个水洼(1678-1685,124-125,138-142)，bot 之前一直淹死在此。需要 h.water 或改走安全路线。
- **goto 智能看门狗**：h.goto 现在带两层：超时（默认8s）+ 停滞检测（位置3.5s没变 >0.4格 即 abort，抛 `goto-stall`）。abort 会 pathfinder.stop+清按键。适合让 agent 介入换路。

## 寻路引擎修复（navmovements.js，已接入 bot.js）
- 根因：pathfinder 的 `Movements.getBlock()` 对 **null 方块（虚空/未加载区块）返回 `physical:false`**，被当可走格 → 会往悬崖/虚空走。这是全局 bug，不是某一处。
- 修复：`NavMovements extends Movements`，覆写 `getBlock()` 使虚空块 `physical:true`（不可通行墙）。同时 `canDig=false`、`allow1by1towers=false`、`allowParkour=false`、`liquidCost=4`（水可走但昂贵，干路优先）。
- 已接入 bot.js spawn 时 `bot.pathfinder.setMovements(new NavMovements(bot))`。验证：bot 从水坑(1685,124,138)走到实心地(1679,131,131)，不再淹死。
- 仍有限制：村长板(1684,143,113)在 y143 高台，bot 在 y131 下层，9格落差，A* 爬不了 → 需走台阶（地图知识，非寻路能解）。
- **村长板所在层**：x=1684,z=113 竖列 y125-140 是实心(stone/dirt)，y142 是 quartz_block。村长板在 y143 平台上，须从村庄上层台阶上。
- **自动吃面包**：bot.food<14 时自动 equip bread + consume。修复"有面包却饿死"（18min 卡墙时 food 0 饿死，hp 15.8→0）。
