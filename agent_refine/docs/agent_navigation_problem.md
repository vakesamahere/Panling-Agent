# 游戏 Agent 的分层导航问题：Setting 与问题定义（讨论稿）

> 用途：供讨论，后续可能整理为会议论文。重点在问题环境 (setting) 与问题定义 (problem)，方案部分只是初步思路。
> 数字约定：文中每个数字标注【实测】或【估计】；没有标注的数字是游戏规格或定义中的常量。

---

## 1. 背景与动机

商业地图导航（人类导航）有几个默认前提：路网由测绘或众包提前给出；"路"是明确的线状结构；执行者是人，能自己处理最后几十米、门、楼梯和突发状况；导航系统只需要给出路线级的指引。

游戏里的 agent 导航不满足这些前提：

1. **执行者没有人的局部能力。** 路线必须细化到每一步动作（跳跃、爬梯、游泳、开门），最后一段"走到 NPC 跟前"也要由系统完成。远程路线和精细走位必须在同一个系统里衔接。
2. **没有显式路网。** 开阔野地处处可走，没有"道路"；洞穴和建筑是三维多层结构。导航图的层级需要自己构造。
3. **存在不可见捷径。** 服务器自定义的传送点通常是"踩到某个位置就传送"，视觉上看不出来，却会改变全局最短路。
4. **代价不只是距离。** 路线可能穿过怪物密集区。危险度是动态的，存档里没有，只能在线获得。
5. **实时性约束。** 规划和战斗、躲避共享同一个控制循环，规划延迟会直接变成"站着挨打"的时间。
6. **地图未必能拿到。** 本地测试服可以读存档，线上服读不到。

因此，问题的核心不是"在一张图上求最短路"，而是：在只有部分先验甚至没有先验的三维体素世界里，同时满足远程效率、局部可执行性、风险控制和实时性。

## 2. Setting

### 2.1 游戏环境

- 平台：Minecraft 1.8 的 RPG 服务器「盘灵古域」。地图为自定义地图，包含村、皇城、大漠等区域。
- NPC：商人、钱庄、任务 NPC 等，是 agent 日常往返的目标。
- 怪物：刷怪点和精英怪。例如「反抗的 千里神射手」：800 血，追踪范围 50 格，弓箭伤害很高。
- 传送：大量服务器自定义传送点，离线图中记录了 159 个传送落点【实测】。触发方式一般是踩到某个位置，视觉上不可辨认。

### 2.2 Agent 能力

- 实现：基于 mineflayer（Node.js）的 bot，职业为弓手。
- 任务：刷怪、出售物资、在 NPC 之间往返。
- 导航需求分两类：
  - 远程导航：几百到上千格。
  - 精细走位：到 NPC 跟前、开门、爬梯子、游泳、跳跃，以及战斗中走位躲箭。

### 2.3 观测

- 服务器把视距内整个区块 (chunk，16×16×256) 的方块数据发给客户端，包括地下方块。所以 bot 的"视野"是视距内的全部方块数据，不是渲染画面，也没有遮挡。
- 怪物和其他实体的位置可实时获得。
- 存档文件：本地测试服可读，线上服不可读。
- 服务器实际视距尚未测量。

### 2.4 现有系统（基线）

- 离线从存档构建格子导航图（PFG3 格式）。地图按 512×512 切分为区域 (region)，共 120 个区域文件，压缩后 161 MB【实测】。
- 每个可站立方块为一个节点。单个区域最多约 34 万个格子、177 万条边【实测】。
- 查询：在格子图上运行 A*。区域按需加载，使用 LRU 缓存。传送作为图中的显式边。
- 执行：规划结果交给跟随器 (follower) 逐段执行。

## 3. Problem：形式化定义

### 3.1 世界与 agent

- **世界**：体素世界 $W: \mathbb{Z}^3 \to \mathcal{B}$，$\mathcal{B}$ 为方块类型集合。$W$ 大部分静态，少量可变（门的开关、玩家改动）。
- **可站立格集合**：$V \subseteq \mathbb{Z}^3$，由 $W$ 和移动规则决定。
- **传送**：触发格集合 $T \subseteq V$ 和映射 $\tau: T \to V$。agent 进入 $t \in T$ 后被移到 $\tau(t)$。$T$ 在视觉上不可辨认。
- **实体**：时刻 $k$ 的实体集合 $E_k$（怪物位置、类型、血量等）。
- **Agent 状态**：$s_k = (p_k, h_k, I_k)$，分别为位置、血量、背包。背包价值记为 $v(I_k)$。
- **动作**：原子移动动作集合 $\mathcal{A}$ = {行走、跳跃、爬梯、游泳、开门、等待, …}。传送不是独立动作，是进入触发格的副作用。
- **转移**：$p_{k+1} = f(p_k, a_k, W)$，若 $p_{k+1} \in T$ 则 $p_{k+1} \leftarrow \tau(p_{k+1})$。血量变化 $h_{k+1}$ 受 $E_k$ 影响，是随机的。

### 3.2 观测

$$o_k = \big(\{W(x) : x \in \text{Chunks}(p_k, R)\},\ E_k\big)$$

其中 $\text{Chunks}(p, R)$ 为以 $p$ 为中心、视距 $R$ 内的全部区块（完整 16×16×256 柱）。观测对方块是完全的（含地下），对传送映射 $\tau$ 是不可见的：只有实际经过触发格才能观测到一次传送。

### 3.3 代价与目标

- **目标**：用谓词 $G(s)$ 表示，而不是单个格子。例如
  $G(s) \equiv \|p - p_{\text{npc}}\| \le 3 \ \wedge\ \text{visible}(p, p_{\text{npc}})$。
- **代价**：一次行程 $\xi$ 的代价
  $$J(\xi) = \mathbb{E}[\text{耗时}(\xi)] + \lambda(s)\cdot \Pr[\text{死亡} \mid \xi]$$
  其中 $\lambda(s)$ 随状态变化，例如随 $v(I)$ 增大、随 $h$ 减小而增大。
- **实时约束**：控制循环每个周期（MC 规格为 20 tick/s，即 50 ms 一个 tick）都要能响应战斗和躲避。任何规划计算不应阻塞控制循环超过一个可接受的上限 $\Delta$。

目标：找到策略 $\pi: (o_{1..k}, M) \to a_k$，在满足实时约束的前提下最小化 $\mathbb{E}[J]$ 并到达 $G$。其中 $M$ 为可用先验，见下面两个设定。

### 3.4 设定 A：完整地图视野

- 先验 $M_A = (W_0, T, \tau)$：离线存档给出静态世界 $W_0$ 和全部传送。
- 先验不包含：实体 $E$（怪物分布与危险度）、存档之后的世界变化。
- 难点：图规模大（单区域 $10^5$ 级节点、$10^6$ 级边，见 2.4）；传送边破坏启发函数（见 4.2）；离线图与实时世界不一致；危险度必须在线学。

### 3.5 设定 B：陌生地图、只有在线观测

- 先验 $M_B = \varnothing$（或仅有少量人工标注）。
- agent 通过 $o_k$ 增量获得 $W$；$\tau$ 只能靠试探或人工标注获得。
- 难点：探索与利用的权衡；第一次去陌生目的地的冤枉路；传送捷径的发现。
- 两类子任务：有目标导航（目标位置已知、路径未知）和无目标探索（建图）。

### 3.6 耦合问题：远程导航与精细走位

把问题拆成"全局规划 + 局部执行"之后，二者之间存在耦合：

1. **可执行性**：全局路径中的每一段必须能被局部控制器执行。离线图认为可走的格子，实时可能不可走（门关着、方块变化、水流），也可能因怪物而不宜走。
2. **目标形式**：全局层给的是位置，任务给的是谓词 $G$。最后一段需要局部层按谓词收敛。
3. **失败传递**：局部失败（卡住、跟丢）需要以某种形式反馈给全局层，否则全局层会反复给出同一条走不通的路线。
4. **时间尺度**：全局规划可以秒级；局部控制必须 tick 级。二者在同一个事件循环里会互相阻塞。

形式上，可以把全局层看作在抽象图 $\hat{G} = (\hat{V}, \hat{E}, \hat{c})$ 上规划，局部层在滑动窗口 $W|_{B(p, r)}$ 上执行。耦合问题即：如何选择抽象 $\hat{G}$、如何设置和更新 $\hat{c}$，使得抽象路径的代价是真实执行代价的良好估计，并且局部失败能使 $\hat{c}$ 收敛到可执行的方案。

## 4. 现有基线与实测问题

### 4.1 规划耗时

缓存 16 块区域时【实测】：

| 路线 | 耗时 | 展开节点 | 路长（格） |
|---|---|---|---|
| 皇城内 12 对地点 | 28–483 ms | 1.9 万–23.5 万 | 160–440 |
| 村莊大門 → 皇城南門 | 63 ms | 4.4 万 | — |
| 村長 → 古董收藏家 | 151 ms | 9 万 | 334 |
| 皇城南門 → 馬賊刷怪點 | 1.37 s | 48 万 | 676 |
| 馬賊刷怪點 → 皇城南門 | 1.69 s | 70 万 | 678 |
| 馬賊刷怪點 → 錢莊 | 1.60 s | 72 万 | 683 |

规划同步执行，阻塞事件循环：长路线约 1.5 s 内战斗 tick 和躲避全部停止【实测】。

### 4.2 启发函数被传送边破坏

为保持可采纳 (admissible)，当前启发函数为

$$h(p) = \min\big(d(p, g),\ \min_{l \in L} d(l, g) + 10\big)$$

$L$ 为传送落点集合，$d$ 为直线距离，10 为传送边的固定代价。第二项没有计入"从 $p$ 走到触发点"的代价，所以只要终点附近有一个落点，$h$ 在全图都很小。实测例子【实测】：

- 馬賊刷怪點 → 皇城南門：直线 583，$h$ 上限只有 26。
- 村長 → 古董收藏家：直线 1602，$h$ 上限只有 41。

A* 因此退化为接近 Dijkstra 的搜索，这是 678 格路线展开 70 万节点的原因。

一个更紧的可采纳下界是

$$h'(p) = \min\big(d(p, g),\ \min_{t \in T} [\,d(p, t) + c_\tau + d(\tau(t), g)\,]\big)$$

（多次传送时需要取多跳的下界，或预计算传送图上的最短距离）。尚未实现和实测。

### 4.3 缓存抖动

【实测】缓存 4 块区域时，一条需要 7 块区域的规划因 LRU 循环淘汰，把区域文件重读了 2415 次，耗时 92 s；缓存 16 块时只读 4 次，耗时 0.39 s。每次重读约 38 ms，主要花在解压和建索引上。改为"单次规划期间不淘汰区域"后，4 块缓存下 12 条路线总耗时降到 2.5 s。

### 4.4 执行失败

失败日志共 106 次【实测】：

| 类型 | 次数 | 说明 |
|---|---|---|
| 中止 | 45 | — |
| 跟丢 | 约 30 | 偏离路径 4–16 格 |
| 卡住 | 26 | 很多卡在村里同一个游泳格子 |
| 找不到格子 | 5 | 起点或终点不在离线图中 |

这说明离线地图与实时世界不一致，且跟随器的局部处理能力不足。

### 4.5 其他

- 实际行走耗时【实测】：人族出生点 → 皇城南门 40–50 s；皇城南门 → 某目的地 102–176 s。
- 边代价只有距离，不含危险度，路线可能穿过怪物密集区。系统已有按区块统计的怪物密度数据，尚未接入代价。

## 5. 初步思路：三层解耦（简述）

| 层 | 粒度 | 规模 | 数据来源 | 职责 |
|---|---|---|---|---|
| L2 战略层 | 地点、传送、区域 | 几百到几千节点 | 离线或在线 | 带价格的全局路线 |
| L1 走廊层 | 区块级 HPA* | 出入口 + 簇内距离 | 离线全量或在线增量 | 把 L2 路线细化为走廊 |
| L0 局部层 | 48–64 格滑动窗口 | 窗口内格子 | 仅实时世界 | 跳跃、梯子、门、游泳、躲怪；按谓词 $G$ 收敛 |

- **层间接口是失败反馈**：L0 走不通时回报上层，调高或封掉对应边的价格，再重新规划。
- **层级识别候选**：区块切分（HPA*）；Contraction Hierarchies / Customizable CH（CCH 适合价格会变的情况）；语义分区，即以瓶颈（门、桥、传送）切分，可借助图划分（METIS、inertial flow）或骨架化。
- **定价**：边代价 = 期望时间 + λ·死亡风险，风险 ≈ 怪密度 × 暴露时间 × 伤害。λ 随背包价值和血量变化。时间用 bot 自身的实际通过时间在线校准，类似地图公司用浮动车数据估计路况。**即使有完整地图，危险度也只能在线学**，因为存档里没有怪。
- **游戏特有难点**：开阔野地没有"路"，骨架化会长出很多分支，可把开阔地整体当作一个区域节点；三维多层结构（洞穴、建筑）要求节点按连通性划分，不能按 xz 坐标划分。
- **设定 B 的做法**：边走边收区块、增量建图。有目标时用 D* Lite 加 freespace assumption；无目标时用 frontier exploration。传送点只能试探或人工标注，是主要难点。
- **设定 B 开销【估计，未实测】**：计算不是瓶颈；第一次去陌生目的地，走冤枉路约 1.2–3 倍，迷宫型洞穴更差；地图缓存后开销与全图版相同；全图扫描约 3100 万平方格，按视距半径 128 估计约 12 万格路程，按 6 格/秒约 6 小时，算上重复约 10 小时，属一次性开销。服务器实际视距未测，以上估计依赖该假设。

**核心论点**：L0 只依赖实时世界，与有没有存档无关；L1 只是数据来源不同（离线全量 vs 在线增量）；L2 的价格在两种设定下都要在线学。所以"完整地图"真正多给的只有两样：第一次去某地的探索代价，以及传送点的位置。这个差距值得量化。

## 6. 开放问题 / 可能的研究贡献点

1. **设定 A 与 B 的效率差距**：如何定义和测量？候选评测协议：第一次到达耗时、累计路程、成功率、多次任务后的摊销代价。差距主要来自探索还是来自传送未知？
2. **动态危险度下的定价**：λ 如何随状态调节？风险模型能否从死亡和受伤数据在线学出？样本稀少（死亡是罕见事件）时如何估计？
3. **自动层级识别的质量评估**：在开放三维体素世界里，用什么指标衡量分区好坏（查询加速、抽象路径次优度、可执行率）？
4. **不可见捷径的发现**：传送点靠主动探索还是先验（NPC 对话、建筑结构、人工标注）？探索预算怎么分配？
5. **规划延迟与实时控制**：anytime 规划、把规划放到非阻塞线程，以及规划未完成时 L0 的默认行为。
6. **L0/L1 失败反馈的收敛性**：调价是否保证终止？如何区分临时阻塞（怪物、门）与永久不可通行，避免过度封边？
7. **启发函数与传送**：带传送边时紧且可采纳的启发函数（如 4.2 的 $h'$、或基于地标的 ALT 类方法）能把展开节点降多少，需要实测。
